## M1：実Jev API接続直前までの自律作業

### 事前許可されたこと

- このForkのコード・文書・人工fixture・テストの追加／修正、必要なビルドと試験、失敗の切り分け、作業ブランチ・commit・push・PR・差分レビュー後のmerge。段階やPRごとに承認を取り直さない。既存変更と他セッションの作業は保持する。
- 試験専用の電卓、既存のメモ帳の新規文書、または自作のローカルテスト画面の起動・表示・前面化・観測。必要なクリック・入力・キー・スクロールは、下記の実行前条件を満たす範囲で許可する。終了時に閉じる／削除してよいのは自分が作った試験用の窓・データだけ。他の文書や計算履歴を消去しない。
- プロジェクト内と専用の一時領域での試験データの作成・保存・上書き・後始末。これは個人ファイルや本番データの変更許可ではない。SBV2のProduction、管理サイト、メール、ログイン済みサービス、別リポジトリは今回の実操作対象外。
- 公式仕様・公開コード・PR・Issueコメントの調査、Gitの通常通信、必要性と副作用を確認したプロジェクト内の依存復元。新規の小さな依存は既存部品・組込み機能と比較し、版・ライセンス・採用理由を記録する。OS全体へのインストールや新サービス契約には広げない。
- 偽キーを使う模擬HTTP、必要なら人工データだけの短命なloopback試験サーバー。LANへ公開しない。実Jev・実キーを使わずに通信処理や失敗経路を検証できる。

GUIの方法は、現在許可されたComputer Useツール／スキルの契約に従う。起動方法が利用できなければ推測APIを作らない。権限拒否をシェル・別ライブラリ・設定変更で迂回しない。アプリ未起動だけなら、許可された方法で起動し、一覧を取り直して続ける。

### 作業順と判定条件

1. **未完の観測を埋める。** 電卓を再特定し、必要なら起動・表示してから状態を取得する。依然として列挙不能なら条件と原因候補を記録し、許可内の試験用画面で独立に確認する。観測できない一項目だけで開発全体を止めない。accessibility:nullは候補未取得であり、空の画面ではない。
2. **D2：読み取り専用adapterを先に完成させる。** 例として`windows-sky-adapter.mjs`に、注入したsky clientを使う一覧・対象選択・状態取得・共通観測への変換を小さく実装する。取得元、取得可否、観測ID／時刻、窓・画像参照を保持する。トップレベルでアプリ起動・観測・通信・秘密読込をしない。null・候補なし・多義的対象・エラー・古い参照を模擬試験し、可能な実機観測を行う。取得不能な構造化形式は未対応として返し、想像でパーサーを作らない。
3. **D3のオフライン準備。** 調査済みの送信先／リダイレクト制限、本文までの期限、応答の型・範囲検証、秘密とログの保護を必要最小限で実装・試験する。選択肢は対象・操作・用意済み引数を一つの操作IDへ結び付け、NONEと非実行の引き継ぎを保持する。同時質問が互いの回答を見ると仮定しない。既知の安全不備を直すことは承認済みの通常作業であり、発見するたびに相談しない。
4. **必要な限定GUI試験。** 実Jevは使わず、Codexの準備操作または固定／模擬判断による1手から確認してよい。新規の実行経路には、許可された対象・引数・現在の観測の一致、直前確認、操作数／期限の上限、実行後の確認を先に備える。これが未整備なら実クリックせず実装と模擬試験を続ける。画像候補はCodexが実画像から抽出し、画像由来と明示する。架空のAX indexを作らず、座標系・倍率・画像原点の契約が未確認なら座標操作しない。結果不明な操作を自動再送しない。1手が検証できたら同じ試験範囲の短い手順へ進めてよい。Jevなしの成功をJevによる成功と報告しない。
5. **レビュー・記録・反映。** 適切な粒度でPRを作り、変更に対応するテスト・安全境界・秘密混入・最新headを確認してmergeする。現行テストが既知の不正な挙動を期待する場合は、理由を説明して回帰試験を修正し、単に全テスト成功を維持するために不備を残さない。STATUSと失敗記録を更新する。

手順ごとの報告は中間報告。許可内で次が明確なら続行する。読み取りadapterの成功だけで止めたり、キー未設定を理由にオフライン実装まで中断したりしない。複数provider、大規模なGUI基盤、汎用文章判定などM1に不要な機能は作らない。

### ユーザーへ戻す境界

| 境界 | 対応 |
|---|---|
| 実Jev API・認証 | M1の準備を終え、実際の接続が必要になった時点で止まる。キーの存在確認を含む.env.localや認証情報の読取り、実APIへの未認証プローブ、課金、契約・チャージはまだ行わない。送信予定の人工データ、リクエスト上限・費用上限案、ローカル設定方法を示して待つ。キーを会話へ貼らせない |
| 重大な問題 | 実際の個人データ破損・秘密漏えいの疑い、誤った窓への操作、影響を限定できない障害、不可逆な操作や本番への影響が必要な場合は該当操作を即時停止。安全な証拠保全・切り分けまでとし、原因と最小の対応案を報告 |
| 大幅な計画変更 | 目的の変更、安全境界の緩和、基盤の全面置換、新たな外部サービス／有料サービス／OS常駐・管理者権限が必要なら相談。局所的なadapter設計、人工fixtureへの切替、画像補助、通常のバグ修正はこの境界ではない |
| ツール・OSの承認や物理的な阻害 | 権限拒否、承認ダイアログ、端末のロック等は勝手に解除しない。自己承認しない。影響のない独立作業を済ませ、必要なユーザー操作を具体的に示す。承認や保護設定を変更して停止回数を減らさない |

通常のimport／パス／型／テスト失敗、電卓未起動、既知のaccessibility:null、説明済みの安全不備は、修正・調査・安全な代案へ進む材料であって、即座にユーザー判断が必要な事態ではない。同じ条件の再試行は原則2回までとし、その後は仮説・条件・観測を変える。解消できない阻害は残し、成功扱いにしない。
