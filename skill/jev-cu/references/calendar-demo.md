# カレンダーの操作例（実行前の計画）

目的は、実際の画面から Jev が操作対象を選び、Computer Use が操作し、Codex が結果を確認する流れを示すことです。表示の切り替えと日付の閲覧だけを行い、予定の作成や変更は行いません。

実行前に「月表示 → 翌月 → 今日 → 週表示」の順を説明します。終了時は今週の表示です。元の表示へ戻す依頼がある場合は、復元を別の段階として扱います。

## 段階と確認条件

| 段階 | Jev に渡す目標 | 確認する結果 |
| --- | --- | --- |
| 月表示 | Switch Calendar to Month view. | month-button が選択されている |
| 翌月 | Navigate to the calendar month immediately after the observed starting month. | 開始時の年月から翌月をコードで求め、タイトルと照合する |
| 今日 | Return to today in Calendar. | 現在の年月で、選択日または表示対象日がローカルの今日と一致する。Today ボタンの存在だけでは不可 |
| 週表示 | Switch Calendar to Week view. | week-button が選択され、表示範囲に今日を含む |

実行前に新しい観測からラベルと状態形式を確認し、目標日はローカルの日付から求めます。古い日付、AX インデックス、例に書かれた固定日を使い回しません。AX で日付を確実に確認できない場合は Codex が画面を確認し、その方法を記録します。Jev には画像を送りません。

まず、実際に操作が必要な段階を1つプレビューします。各段階は最大2～3手とし、完了を確認してから次へ進みます。ダイアログ、ユーザーによる画面変更、期待した変化の欠落があれば停止して再判断します。

## 記録

各段階の目標、操作前後の必要な状態要約、ログの場所、Jev 呼び出し数、実操作数、所要時間、検証結果、引き継ぎ理由を保存します。無関係な予定の本文は保存しません。

これは操作経路の実演案です。他方式より高速・低コストであることを証明するものではありません。比較する場合は開始状態と成功条件を揃え、失敗と介入も数えます。
